# Skill operacional — cc-flow (ponteiro)

**Procedimento executável e canônico:** [`.claude/skills/cc-flow/SKILL.md`](../../.claude/skills/cc-flow/SKILL.md)

**Relacionadas:** `git-closure-skill.md`, `execution-report-skill.md`, `pedagogical-checkpoint-skill.md` — cc-flow orquestra as 3, sem duplicar nenhuma.

Sequencia, numa unidade de trabalho que toca Git, as 3 skills operacionais na
ordem em que 7+ ciclos reais (PRs #13, #15, #19, #21, #22, #23) já as usavam:
Checkpoint 0/1 → **pré-voo de branch** (item novo: checar/criar a branch
imediatamente após a aprovação do plano, antes de qualquer edição) → editar →
relatório → Checkpoint 2 → Gate 1 → Gate 2 → PR → Gate 3 (merge humano) →
Checkpoint 3 → Gate 4 → Checkpoint 4 (parar).

Este arquivo é só o ponteiro legível. Qualquer mudança de procedimento é feita
na versão executável; em divergência, valem a executável e, acima dela, as
Regras 14/15/16.
